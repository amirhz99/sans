# مسئول سانس فوتبال ⚽

ربات فارسی بله برای مدیریت سانس، حضور، مهمان، بدهی و رسید پرداخت؛ با **Python 3.12+، SQLite و API هوش مصنوعی OpenAI-compatible**. بدون پنل وب، ORM، سرویس دیتابیس جداگانه؛ تنها وابستگی‌های pip مربوط به لایهٔ AI است و در `requirements.txt` آمده‌اند. اجرای فعلی برای Linux است.

## امکانات

- مکالمهٔ آزاد فارسی برای ادمین و بازیکن؛ فرمان‌های جایگزین در زمان قطع AI.
- هزینهٔ کل زمین و سهم ثابت هر نفر، دو مبلغ مستقل برای هر سانس.
- ثبت حضور با تعداد مهمان؛ هر مهمان یک سهم کامل به حساب میزبان اضافه می‌کند.
- دفتر مالی تراکنشی: بدهی سانس، پرداخت، بدهی اولیه و اصلاح حساب با توضیح.
- پرداخت جزئی و بستانکاری؛ گزارش ماندهٔ هر سانس با تخصیص پرداخت‌ها به قدیمی‌ترین بدهی.
- توضیح عمومی پرداخت، توضیح شخصی بازیکن و یادداشت هر سانس.
- معرفی اولیهٔ کاربر، پیشنهاد تطبیق نام فارسی و اتصال حساب پس از تأیید ادمین.
- ارسال عکس یا سند رسید به گروه، تأیید/رد ادمین و اطلاع به کاربر.
- حالت ثبت خودکار رسید، **خاموش به‌صورت پیش‌فرض**؛ بدون ادعای بررسی بانکی.
- نمایش بدهی هر نفر و گزارش کلی در گروه مدیریتی تنظیم‌شده؛ همهٔ اعضای همان گروه ادمین محسوب می‌شوند.
- پرسش دوره‌ای از ادمین‌ها دربارهٔ اطلاعات ناقص و یادآوری بررسی رسید/هویت.
- ورود CSV اولیه بدون حساب بله، بکاپ سازگار SQLite، تاریخچهٔ تغییرات و صف ارسال پایدار.

### متن‌ها و پیش‌فرض‌های قابل کنترل

متن prompt هوش مصنوعی، راهنمای کاربر و راهنمای ادمین، به‌همراه پیش‌فرض‌های ساخت سانس، همگی در فایل زیر قرار دارند:

`/root/sans/content/bot-content.json`

پیش‌فرض فعلی برای سانس جدید:

- محل: **سالن فوتسال تیموری**
- هزینهٔ کل زمین: **۲٬۵۰۰٬۰۰۰ تومان**
- سهم هر نفر: **۱۵۰٬۰۰۰ تومان**
- فرمول بدهی: سهم هر نفر × (۱ + تعداد مهمان)

ادمین می‌تواند برای هر سانس مقدار متفاوتی اعلام کند؛ مقدار صریح ادمین بر پیش‌فرض غلبه دارد. زمان دقیق استثناست و باید اعلام شود؛ عبارت‌هایی مثل «امروز عصر» ثبت نمی‌شوند و ربات ساعت دقیق را می‌پرسد. زمان‌های جدید در ستون `session_at` به‌صورت ISO با timezone `Asia/Tehran` ذخیره می‌شوند و عبارت اصلی کاربر در `when_text` نیز باقی می‌ماند. تغییر این فایل از سانس‌های قبلی یا بدهی‌های ثبت‌شده اثر نمی‌گیرد و برای بارگذاری متن جدید، سرویس را restart کنید. ادمین‌ها می‌توانند با `/config` تنظیمات فعلی، متن پرداخت، وضعیت تأیید رسید و قیمت سانس‌های باز را ببینند.

## راه‌اندازی

در بله از `@botfather` توکن بگیرید و ربات را به گروه خصوصی ادمین‌ها اضافه کنید. دسترسی دریافت پیام‌های گروه و ارسال پیام/عکس/فایل باید فراهم باشد. همهٔ افراد گروه را مورد اعتماد در نظر بگیرید، چون پاسخ‌های ربات برای تمام اعضای گروه دیده می‌شود.

```bash
cp /root/sans/.env.example /root/sans/.env
chmod 600 /root/sans/.env
```

فایل `/root/sans/.env` را تکمیل کنید:

| تنظیم | توضیح |
| --- | --- |
| `BALE_BOT_TOKEN` | توکن بله |
| `ADMIN_GROUP_ID` | شناسهٔ عددی گروه مدیریتی |
| `ADMIN_USER_IDS` | سازگاری با تنظیمات قدیمی؛ برای دسترسی گروهی جدید لازم نیست |
| `ADMIN_ACCESS` | سازگاری با تنظیمات قدیمی؛ دسترسی مدیریتی فقط بر اساس `ADMIN_GROUP_ID` است |
| `AI_BASE_URL` | آدرس پایهٔ HTTPS سرویس، معمولاً با انتهای `/v1`؛ نه مسیر کامل chat/completions |
| `AI_API_KEY` | کلید سرویس |
| `AI_MODEL` | نام مدل در همان سرویس |
| `AI_FALLBACK_MODEL` | اختیاری؛ نام یک یا چند مدل جایگزین با کاما. اگر مدل اصلی خطا بدهد (مثلاً سهمیه/۴۰۲)، همان درخواست با مدل بعدی تکرار می‌شود |
| `DATABASE_PATH` | پیش‌فرض: `/root/sans/data/sans.sqlite3`؛ مسیر نسبی نسبت به ریشهٔ پروژه تفسیر می‌شود |
| `BOT_NAME` | پیش‌فرض: `مسئول`؛ واژهٔ خطاب در گروه |
| `REMINDER_HOURS` | فاصلهٔ یادآوری‌ها، پیش‌فرض ۲۴ ساعت؛ صفر یعنی خاموش |

متغیرهای محیطی سیستم بر مقادیر فایل اولویت دارند. فایل env ساده است و از expansion یا کامنت انتهای مقدار پشتیبانی نمی‌کند.

### به‌دست‌آوردن شناسه‌ها

فقط توکن را در `/root/sans/.env` وارد کنید. هر ادمین در خصوصی ربات و در گروه `/id` بفرستد. سپس، در حالی که نمونهٔ دیگری از ربات اجرا نیست:

```bash
python3 /root/sans/run.py --discover-ids
```

این فرمان شناسهٔ گفتگو و فرستنده را از پیام‌های اخیر چاپ می‌کند؛ متن پیام یا توکن را چاپ نمی‌کند. با این اطلاعات `ADMIN_GROUP_ID` را تکمیل کنید. در رباتِ در حال اجرا هم `/id` در دسترس است. `ADMIN_USER_IDS` فقط برای سازگاری با تنظیمات قدیمی نگه داشته شده و مرز دسترسی فعلی نیست.

فقط گروهی که `ADMIN_GROUP_ID` مشخص می‌کند فعال است و همهٔ اعضای آن گروه، بدون نیاز به فهرست شناسه‌ها، ادمین محسوب می‌شوند. پیام، منشن، ریپلای، دستور، مدیا و دکمه از هر گروه یا سوپرگروه دیگر نادیده گرفته می‌شود؛ گفت‌وگوهای خصوصی برای قابلیت‌های عادی کاربران فعال می‌مانند و ادمین گروهی نیستند. این دسترسی از اطلاعات فرستنده/گفتگوی ارسالی API بله استفاده می‌کند، نه استعلام مستقل عضویت در هر کلیک. دسترسی به خود گروه، لینک دعوت و اضافه‌شدن اعضای جدید را محدود کنید؛ اعضای جدید هم بلافاصله این دسترسی را خواهند داشت.

### ساخت دیتابیس و اجرا

```bash
python3 /root/sans/run.py --init
python3 /root/sans/run.py
```

ساخت جداول خودکار است؛ `--init` برای بررسی آفلاین مفید است و توکن نمی‌خواهد. برنامه با long polling اجرا می‌شود؛ پورت ورودی عمومی نیاز ندارد. خروج با `Ctrl+C` است. برای اجرای دائمی از مدیر سرویس سرورتان استفاده کنید.

اگر قبلاً برای همین توکن webhook تنظیم کرده‌اید، ابتدا از API بله `deleteWebhook` را فراخوانی کنید. برنامه webhook موجود را خودکار حذف نمی‌کند. فقط **یک نمونهٔ فعال** برای هر توکن/دیتابیس داشته باشید؛ قفل محلی جلوی اجرای هم‌زمان روی یک دیتابیس را می‌گیرد، نه استفادهٔ همان توکن روی سرور دیگر.

### اجرای محلی برای توسعه

روی ماشین توسعه (بدون systemd و بدون root) همین مخزن کافی است:

```bash
git clone git@github.com:amirhz99/sans.git
cd sans
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env && chmod 600 .env
.venv/bin/python3 run.py --init
.venv/bin/python3 run.py
```

روی ویندوز، مسیر مفسر `.venv\Scripts\python.exe` است (مثلاً `.venv\Scripts\python.exe run.py`).

`BALE_BOT_TOKEN`، `ADMIN_GROUP_ID` و کلید/مدل AI را در `.env` بگذارید. فایل `.env`، پوشهٔ `data/` و همهٔ `*.sqlite3*` در git نیستند؛ برای کار روی دادهٔ واقعی، `data/sans.sqlite3` را جداگانه (مثلاً با `scp`) کپی کنید و همان مقدار `DATABASE_PATH` را تنظیم کنید (فایل `data/sans.sqlite3.lock` را کپی نکنید). روی ویندوز، بستهٔ `tzdata` در `requirements.txt` لازم است تا `Asia/Tehran` شناسایی شود.

تست‌ها توکن و شبکه لازم ندارند:
```bash
python3 -m unittest discover -s tests -t . -v
python3 -m compileall -q app tests
```

برای هر توکن فقط **یک** نمونهٔ long polling اجرا کنید. پیش از اجرای محلی، سرویس سرور را متوقف نگه دارید (`systemctl stop sans-bot.service`)؛ قفل محلی فقط جلوی دو نمونه روی یک دیتابیس را می‌گیرد، نه همان توکن روی دو ماشین.

### اجرای دائمی روی همین سرور

نمونهٔ سرویس در `/root/sans/deploy/sans-bot.service` است. این نمونه برای همین مسیر و اجرای کاربر root نوشته شده، کد/تنظیمات را فقط خواندنی می‌کند و نوشتن را به پوشهٔ داده محدود می‌کند. برای جابه‌جایی پروژه مسیرها و کاربر سرویس را بازبینی کنید.

```bash
install -m 644 /root/sans/deploy/sans-bot.service /etc/systemd/system/sans-bot.service
systemctl daemon-reload
systemctl enable --now sans-bot.service
systemctl status sans-bot.service --no-pager
journalctl -u sans-bot.service -n 30 --no-pager
```

پس از تغییر `/root/sans/.env`، دستور `systemctl restart sans-bot.service` را اجرا کنید. برای ورود CSV یا بکاپ، ابتدا `systemctl stop sans-bot.service` و پس از پایان `systemctl start sans-bot.service` بزنید. گزینهٔ `--discover-ids` یا polling مستقل را هم‌زمان با سرویس اجرا نکنید (`--discover-ids` گزینهٔ CLI است، نه فرمان ربات).

اعتبار کلید یا دریافت فهرست مدل‌ها، تضمین موفقیت chat/completions نیست. در InferHub شناسهٔ مدل ممکن است به پیشوند ارائه‌دهنده مثل `ali/qwen3.8-flash` نیاز داشته باشد. خطای HTTP 402 با پیام `no provider's ask matches your max-per-mtok bid` به پیدا نشدن ارائه‌دهنده در سقف قیمت پیشنهادی اشاره دارد. تنظیمات قیمت/مسیریابی حساب را نزد سرویس بررسی کنید؛ ربات سقف هزینه را خودکار افزایش نمی‌دهد. در زمان خطای AI، فرمان‌های قطعی همچنان در دسترس‌اند.

## ورود اطلاعات قبلی

ساختار نمونه در `/root/sans/examples/players.csv` آمده است. فایل UTF-8 با سرستون‌های زیر بسازید:

```csv
name,opening_balance,note
علی رضایی,300000,بدهی دو سانس قبلی
رضا محمدی,0,
محمد احمدی,-50000,بستانکاری قبلی
```

عدد مثبت یعنی بدهکار، منفی یعنی بستانکار. همهٔ مبلغ‌ها **تومان** هستند. حساب بله لازم نیست؛ بعداً هنگام معرفی و تأیید ادمین متصل می‌شود.

پس از قرار دادن اطلاعات واقعی خودتان در `/root/sans/players.csv`، ربات را متوقف و اجرا کنید:

```bash
python3 /root/sans/run.py --import-players /root/sans/players.csv
```

برای snapshot حساب اعضا از فایل Excel نیز می‌توان استفاده کرد:

```bash
python3 /root/sans/run.py --import-players '/root/sans/football-account(1).xlsx'
```

در Excel، مبالغ ستون «مجموع بدهکاری» هزار تومان هستند و به تومان تبدیل می‌شوند. اگر این ستون برای یک نفر واقعاً خالی باشد، بدهی آن ردیف برابر با «جلسات آمده × ۱۵۰٬۰۰۰ تومان» محاسبه می‌شود؛ صفر صریح همچنان صفر است. توضیح همهٔ بدهی‌های این snapshot دقیقاً `بدهی تا آخر شهریور` ثبت می‌شود. ورود Excel snapshot قبلیِ opening را جایگزین می‌کند، روی بدهی‌های سانس‌ها و پرداخت‌های ثبت‌شده دست نمی‌زند، تراکنشی است و اجرای دوبارهٔ همان فایل مبلغ را جمع نمی‌کند.

ورود فایل تراکنشی است: هر خط نامعتبر باشد کل ورود برمی‌گردد. ورود تکراری همان فایل دوباره بدهی ایجاد نمی‌کند. تغییر ماندهٔ اولیهٔ واردشده مجاز نیست؛ اصلاح مالی را از ربات با دلیل ثبت کنید. نام کامل باید یکتا باشد؛ برای هم‌نام‌ها پسوند متمایز بگذارید. ورود اولیه تاریخچهٔ سانس‌های گذشته را بازسازی نمی‌کند؛ یک «ماندهٔ اولیه» با توضیح می‌سازد.

**فایل واقعی اعضا را وارد Git نکنید.** بهتر است آن را در `/root/sans/data/players.csv` که نادیده گرفته می‌شود نگهداری کنید و مسیر فرمان را مطابق آن تغییر دهید.

## گردش کار ادمین

در گروه، ربات تنها به فرمان‌های `/...`، ریپلای به خودش، منشن نام کاربری‌اش یا پیام‌های دارای واژهٔ `مسئول` پاسخ می‌دهد؛ مکالمات عادی گروه را به AI نمی‌فرستد.

سلام خالی هم مثل یک پیام آزاد به AI می‌رود و پاسخ کوتاه می‌گیرد؛ در گروه فقط سلامِ خطاب‌شده (مثلاً «مسئول سلام») پاسخ داده می‌شود. سلام خالی هیچ عملیات یا پیشنهادی نمی‌سازد و اگر سرویس AI پاسخ معتبر ندهد، یک پاسخ کوتاه ثابت می‌فرستد.

مثال‌ها:

```text
مسئول، یک سانس به اسم پنجشنبه ۲۳ مهر ثبت کن؛ ساعت ۲۱، زمین آزادی؛ هزینه زمین ۲۴۰۰۰۰۰ تومان و سهم هر نفر ۱۵۰۰۰۰ تومان.
مسئول، علی رضایی در سانس پنجشنبه ۲۳ مهر با دو مهمان آمد و رضا محمدی تنها آمد.
مسئول، حساب سانس پنجشنبه ۲۳ مهر را نهایی کن.
مسئول، بدهی علی رضایی چقدر است؟
مسئول، توضیح علی رضایی را بگذار «این مبلغ شامل سهم مهمان‌ها هم هست».
مسئول، شماره کارت را به ۶۰۳۷... به نام صاحب حساب تغییر بده.
```

ربات خلاصهٔ عملیات را برای تأیید نشان می‌دهد. **قبل از تأیید، مبلغ، واحد، نام، تاریخ و تعداد مهمان را بررسی کنید**؛ مدل ممکن است اشتباه کند. برای عدد مبهم مثل «۱۵۰ تومن» باید مقدار دقیق اعلام شود. زمان سانس جدید به‌صورت ISO با timezone تهران ذخیره می‌شود؛ `when_text` متن اصلی کاربر است و سانس‌های قدیمی بدون زمان ساختاری مهاجرت خودکار نمی‌شوند. تاریخ‌ها را می‌توان شمسی نوشت: «۹ خرداد ساعت ۲۱»، «۹ خرداد ۱۴۰۴ ساعت ۲۱» یا «۱۴۰۵/۰۳/۰۹ ۲۱:۰۰»؛ اگر سال ننویسید سال جاری شمسی در نظر گرفته می‌شود. تاریخ‌های نسبی «امروز»، «فردا»، «پس‌فردا»، روزهای هفته و تاریخ میلادی `YYYY-MM-DD` هم پشتیبانی می‌شوند. ساعت‌های مبهم مثل «۹» یا بازهٔ مبهم «عصر» پذیرفته نیستند. ترجیحاً تاریخ و ساعت ۲۴ساعته بنویسید. تاریخ‌ها در پاسخ‌ها و فهرست سانس‌ها شمسی نمایش داده می‌شوند.

### محاسبهٔ بدهی

```text
بدهی شخص در یک سانس = سهم ثابت همان سانس × (۱ + تعداد مهمان‌ها)
```

مثلاً سهم ۱۵۰٬۰۰۰ تومان و دو مهمان یعنی ۴۵۰٬۰۰۰ تومان. مبلغ ۲٬۴۰۰٬۰۰۰ تومان زمین فقط برای گزارش هزینه است و در این فرمول نقشی ندارد.

۱. سانس را با زمان دقیق (مثلاً «فردا ساعت ۲۱» یا «پنجشنبه ۲۱:۳۰») بسازید و سهم هر نفر را مشخص کنید؛ هزینهٔ زمین اختیاری است.
۲. حضورها را ثبت/اصلاح کنید. ثبت مجدد حضور، تعداد مهمان را **جایگزین** می‌کند.
۳. با درخواست «نهایی کن»، خلاصهٔ تمام بدهی‌های پیشنهادی را ببینید و تأیید کنید.
۴. در این مرحله بدهی ثبت و به بازیکن‌های دارای حساب متصل اطلاع داده می‌شود.

تا قبل از نهایی‌سازی، حضور بدهی ایجاد نمی‌کند. پس از نهایی‌سازی، حضور و سهم سانس قفل هستند؛ برای اصلاح، یک تراکنش اصلاح حساب با توضیح ثبت کنید تا سابقه پاک نشود. سانس جدید مبلغ مستقل دارد. اگر چند سانس باز باشد ربات عنوان/شناسهٔ دقیق می‌پرسد؛ حدس نمی‌زند.

### اصلاح هویت بازیکن

اگر هنگام ورود اطلاعات قدیمی نام کوتاه یا ناقص ثبت شده باشد، سه راه دارید:

- **تغییرنام:** `/rename 15 محمد مهدی موحد` یا «مسئول، اسم بازیکن ۱۵ رو بکن محمد مهدی موحد». شناسه و همهٔ سوابق حفظ می‌شود.
- **ادغام:** `/merge 12 18` رکورد ۱۲ را در ۱۸ ادغام می‌کند؛ حضور، دفترکل و رسیدها منتقل و رکورد تکراری حذف می‌شود. ادغام همیشه دکمهٔ تأیید دارد.
- **حذف:** `/delplayer 4` فقط برای رکوردی که هیچ حضوری ندارد. اگر تاریخچه داشته باشد، ربات پیشنهاد ادغام می‌دهد.

ربات دیگر برای نام ناشناس در ثبت حضور بازیکن نمی‌سازد؛ اگر نام با یک بازیکن موجود مشابه باشد، همان‌ها را با `#شناسه` نشان می‌دهد و نام کامل را می‌پرسد. ادغام در این حالت‌ها انجام نمی‌شود: هر دو بازیکن به یک حساب بله متصل باشند، درخواست منتظری به آن‌ها اشاره کند، یا مهمان‌های رکورد تکراری از رکورد اصلی بیشتر باشد (خطر گم‌شدن مهمان). پس از ادغام، ادامهٔ گفت‌وگو به بازیکن باقی‌مانده اشاره می‌کند و پس از حذف، اشارهٔ قبلی پاک می‌شود؛ ارجاع به بازیکن حذف‌شده هرگز به مدل فرستاده نمی‌شود.

برای انجام تغییرات بدون AI از `/do` با JSON استفاده کنید؛ همچنان تأیید لازم است:

```text
/do {"action":"new_player","args":{"name":"علی رضایی","note":""}}
/do {"action":"new_session","args":{"title":"پنجشنبه ۲۳ مهر","when_text":"پنجشنبه ساعت ۲۱","location":"آزادی","venue_cost":2400000,"person_fee":150000}}
/do {"action":"attendance","args":{"session":1,"player":1,"guests":2}}
/do {"action":"attendance","args":{"session":1,"player":1,"present":false}}
/do {"action":"finalize","args":{"session":1}}
/do {"action":"adjustment","args":{"player":1,"amount":-50000,"note":"تخفیف با توافق ادمین"}}
/do {"action":"settings","args":{"key":"card","value":"شماره کارت و نام صاحب حساب"}}
/do {"action":"settings","args":{"key":"payment_note","value":"لطفاً تا جمعه تسویه کنید؛ بعد از واریز رسید بفرستید."}}
/do {"action":"settings","args":{"key":"approval_required","value":false}}
```

دستورهای دسته‌ای تا ۲۰ حضور یا بازیکن جدید پشتیبانی می‌شوند؛ هر دسته اتمی است. ثبت بازیکن و استفاده از شناسهٔ جدیدش در همان دسته پشتیبانی نمی‌شود. ابتدا بازیکن‌ها را بسازید.

## گردش کار بازیکن و رسید

۱. کاربر در خصوصی نام کاملش را می‌گوید یا `/identify علی رضایی` می‌فرستد. برای اینکه ادمین‌ها بتوانند او را راحت‌تر تشخیص دهند، کاربر می‌تواند contact شمارهٔ خودش را هم در خصوصی برای ربات بفرستد؛ username، نام نمایشی و شماره فقط در درخواست ادمین نمایش داده می‌شوند. شمارهٔ contact شخص دیگر پذیرفته نمی‌شود.
۲. حتی تطبیق دقیق نام نیاز به تأیید ادمین دارد؛ پیش از تأیید، بدهی افشا نمی‌شود. برای نام مبهم، ادمین با `/link` شخص درست را مشخص می‌کند. هیچ فهرست نام خصوصی برای کاربر ناشناس فرستاده نمی‌شود.
برای تطبیق مستقیم ادمین، به پیام profile/contact/forward دارای شناسهٔ عددی ریپلای کنید و در گروه مدیریتی `/bind نام بازیکن [@username]` بفرستید. username فقط کنترل سازگاری است و به‌تنهایی شناسه محسوب نمی‌شود؛ پیام بدون شناسه، شناسهٔ ربات، mismatch یا حساب/بازیکن متصل‌شده رد می‌شود. اتصال تا زدن دکمهٔ تأیید pending می‌ماند.
۳. پس از اتصال، `/start`، `/debt` و پیام فارسی برای حساب خودش کار می‌کنند. `/card` بدون نیاز به تأیید هویت در دسترس است. کاربر عادی نمی‌تواند بدهی دیگران را بگیرد.
۴. عکس/فایل رسید را می‌فرستد و مبلغ دقیق را در کپشن عددی، پیام بعدی یا `/amount 150000` اعلام می‌کند. OCR انجام نمی‌شود.
۵. رسید و مبلغ اعلامی به گروه ادمین‌ها می‌رود. در حالت پیش‌فرض، تا زمان تأیید هیچ مبلغی از بدهی کم نمی‌شود.
۶. تأیید باعث کسر **مبلغ پرداخت** می‌شود، نه پاک‌شدن تمام بدهی. اضافه‌پرداخت بستانکاری ایجاد می‌کند؛ رد رسید مانده را تغییر نمی‌دهد.

در حالت `approval_required=false`، دریافت رسید **همراه مبلغ معلوم** کافی است و پرداخت خودکار ثبت می‌شود. رسیدهای قبلیِ منتظر، با تغییر تنظیم خودکار تأیید نمی‌شوند. `/cancel` رسیدِ هنوز ثبت‌نشده را کنار می‌گذارد، نه پرداخت تأییدشده یا رسید منتظر ادمین را.

**هشدار:** این سیستم به بانک متصل نیست. file_id / file_unique_id تکراری دوباره ثبت نمی‌شود، ولی عکس ویرایش‌شده یا بارگذاری متفاوت ممکن است شناسهٔ دیگری داشته باشد. تشخیص انتقال بانکی تکراری، اصالت تصویر، مبلغ و مقصد بر عهدهٔ ادمین است. رسید ردشده با همان شناسهٔ فایل مجدداً ثبت نمی‌شود؛ برای اشتباه ادمین از اصلاح حساب مستند استفاده کنید.

## حریم خصوصی و قابلیت اطمینان

- AI صرفاً JSON پیشنهاد می‌دهد؛ SQL، تأیید پرداخت یا اجازهٔ دسترسی از مدل پذیرفته نمی‌شود.
- نام ادمین یا جملهٔ «من ادمینم» مجوز نیست؛ فقط گروه مدیریتی تنظیم‌شده مرز دسترسی است. پیام‌های همهٔ گروه‌های دیگر قبل از AI، لاگ و پردازش مدیا رد می‌شوند.
- مدل فقط متن، تاریخچهٔ محدود همان فرستنده/گفتگو و context لازم را می‌گیرد. در گروه فهرست نام/شناسهٔ بازیکن‌ها هم برای تطبیق ارسال می‌شود. عکس رسید برای AI ارسال نمی‌شود. تاریخچه ممکن است شامل ماندهٔ حساب یا شماره کارتِ پاسخ قبلی باشد؛ سرویس قابل اعتماد انتخاب کنید و کاربران را مطلع کنید.
- مرجع فایل رسید در SQLite نگه داشته می‌شود و خود فایل با API بله مجدداً برای ادمین ارسال می‌شود. **بکاپ دیتابیس، آرشیو مستقل تصاویر رسید نیست**؛ ماندگاری دسترسی به رسانه وابسته به بله است.
- پیام‌های ورودی، وضعیت مکالمه، درخواست‌های منتظر و صف خروجی پایدارند. اجرای دوبارهٔ همان update یا تأیید دوباره، تراکنش مالی جدید نمی‌سازد.
- پیشنهاد تغییرات پس از ۲۴ ساعت یا هر تغییر ثبت‌شدهٔ دیگر منقضی می‌شود؛ دوباره درخواست بدهید تا خلاصهٔ تازه نمایش داده شود. ادمین می‌تواند کارت‌های منتظر را زودتر با `/expire [ساعت]` ببندد (`/expire 0` یعنی همه)؛ بستن کارت هیچ حساب، سانس یا رسیدی را تغییر نمی‌دهد. درخواست هویت تا بررسی/لغو باقی می‌ماند و با این فرمان بسته نمی‌شود.
- ارسال خروجی retry دارد؛ اگر بله پیام را گرفته باشد ولی پاسخ شبکه گم شود، **اعلان ممکن است تکرار شود**؛ تراکنش مالی دوباره اعمال نمی‌شود. خطاهای ارسال در log می‌آیند و پیام در صف باقی می‌ماند.
- یادآوری‌ها هنگام اجرای برنامه بررسی می‌شوند؛ تایمر دقیق تقویمی، پیامک یا پیگیری خارج از بله وجود ندارد. سؤال مشابه در کمتر از ۶ ساعت تکرار نمی‌شود.
- SQLite رمزگذاری‌شده نیست. فایل دیتابیس، بکاپ‌ها، CSV و `.env` را محرمانه نگه دارید. برنامه فایل‌های تازه را با دسترسی خصوصی ایجاد می‌کند.

## بکاپ و تست

ربات را متوقف کنید. مقصد بکاپ باید جدید باشد:

```bash
python3 /root/sans/run.py --backup /root/sans/data/backup-2026-10-15.sqlite3
python3 -m unittest discover -s /root/sans/tests -t /root/sans -v
```

بکاپ از API خود SQLite استفاده می‌کند تا WAL باعث نسخهٔ ناقص نشود. برای بازیابی، در حالت توقف از مسیر فایل بکاپ به‌عنوان `DATABASE_PATH` استفاده کنید. فایل‌های WAL قدیمی را کنار دیتابیس جایگزین‌شده رها نکنید.

تست‌ها آفلاین‌اند و از دیتابیس موقت و کلاینت ساختگی استفاده می‌کنند: مهمان‌ها، مانده‌ها، ورود اولیه، اتصال هویت، محدودیت دسترسی، رسیدها، پردازش تکراری، تأیید قدیمی، rollback دسته‌ای و retry شبکه. برای smoke-test واقعی باید توکن بله و تنظیمات سرویس مدل خودتان را بدهید؛ سازگاری مدل انتخابی و دسترسی گروه نیاز به بررسی با همان سرویس دارند.
