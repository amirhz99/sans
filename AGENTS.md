# Agent Contract

This repository uses a small, tool-independent Spec-Driven Development (SDD)
workflow. An agent working on the project must read this file and the relevant
file in `specs/` before changing code.

## Workflow

Use this order for every non-trivial change:

1. Read the relevant specification and existing implementation/tests.
2. Define or update acceptance criteria before implementation.
3. Add or update executable tests for the criteria.
4. Make the smallest implementation change that satisfies the tests.
5. Run targeted tests, then the complete validation commands below.
6. Update the specification status and record relevant limitations.

The canonical lifecycle is:

```text
spec -> plan -> implement -> test -> review
```

## Architecture constraints

- Keep domain contracts in `app/domain/` dependency-free and explicit.
- Treat AI output as an untrusted request. Validate `Intent` before routing it.
- Unknown actions, malformed arguments, invalid entities, and invalid response
  levels must fail closed; they must not cause a side effect.
- Keep context role-aware and minimal. Do not send the complete player
  directory, secrets, receipt contents, `.env` values, or unrelated history to
  the model.
- Use `last_entity` only as a bounded follow-up reference; do not infer an ID
  that is absent from the validated context.
- Keep `summary` as the default response level. Details and full views require
  an explicit request and must respect the caller's role.
- Do not change financial rules, ledger semantics, or the SQLite schema unless
  a dedicated specification explicitly authorizes it.
- Preserve public compatibility paths such as `Service.session_info()` and
  legacy prompt content formats unless a specification says otherwise.
- Use only the Python standard library and dependencies already present in the
  repository.

## Test and validation commands

Run these from the repository root:

```bash
python3 -m unittest discover -s tests -t . -v
python3 -m compileall -q app tests
git diff --check
```

For a quick invocation, `python3 -m unittest discover -s tests -v` is also
acceptable when run from the repository root.

## Change hygiene

- Keep each patch focused on its specification.
- Prefer a focused regression test over broad test rewrites.
- Do not commit `.env`, database files, logs, generated bytecode, or receipt
  media.
- Report skipped tests and environment-dependent limitations explicitly.
